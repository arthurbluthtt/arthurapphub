# D2 Wishlist — `/destiny`

Wishlist personal de armas de Destiny 2. Login requerido (`/destiny`).

## Qué hace

Modal "Agregar arma" con búsqueda de arma por nombre + 4 inputs manuales para perks (Cañón / Cargador / Rasgo 1 / Rasgo 2). El usuario tipéa; el server resuelve cada perk por nombre en el manifest oficial de Bungie y, si no existe, la guarda como "custom" con placeholder SVG. Cada card muestra el arma + 4 perks con iconos + badge de tier + botón editar + toggle "Encontrada".

## Datos

- **Manifest**: `data/d2/weapons-index.json` + `data/d2/perks.json`, generados con `npm run build:d2-manifest` (requiere `BUNGIE_API_KEY`). 2058 armas con `weaponType` real (vía `DestinyItemCategoryDefinition`) y 2000 perks indexadas; `category` viene de `itemTypeDisplayName` cuando Bungie la proporciona y tiene fallback legacy en `perks/match.ts`.
- **Mapeo de sub-categorías a slots canónicos** (whitelist por slot en `perks/match.ts`):
  - `barrel` ← Barrel, Bowstring, Scope, Sight, Launcher Barrel, Guard, Enhanced Guard, Stock, Grip, Grips, Handle, Tang, Rail, Praxic Blade Form
  - `magazine` ← Magazine, Battery, Arrow
  - `perk1`/`perk2` ← Trait, Enhanced Trait
- **Blacklist global** (nunca trackeables): Intrinsic, Weapon Ornament, Origin Trait, Enhanced Origin Trait, Weapon Mod, Enhanced Weapon Mod, Memento, Shader, Combat Flair, Resonant Material, Restore Defaults.
- **Normalización al guardar**: `add.ts`/`update.ts` usan `SLOT_CATEGORY` — la perk queda con la categoría del slot donde el usuario la puso, no la del manifest.
- **Fallback legacy**: si el manifest no tiene `category`, `perks/match` clasifica por regex (`barrel|sights|scope|launcher` → barrel; `mag|magazine|rounds|cartridge|battery` → magazine; resto → trait). Un rebuild del manifest elimina la dependencia.
- **Referencias del snapshot**: `perkPoolHashes` y `mainPerkHashes` solo publican hashes presentes en `perks.json`; algunos `mainPerkHashes` quedan vacíos en armas legacy cuando Bungie no expone dos sockets principales.
- **Iconos**: `D2_ASSETS` (R2) `weapons/<hash>.png` + `perks/<hash>.png`. Primer hit baja del CDN de Bungie → R2 → cache 30 días. Iconos custom en D1 `d2_perk_icons` con `category` asignable.

## API

| Método | Ruta | Body / Query | Respuesta |
|---|---|---|---|
| `GET` | `/destiny/api/search?q=` | — | `{result: Weapon \| null}`; una única mejor coincidencia, priorizando nombre exacto, prefijo y después substring (case-insensitive) |
| `GET` | `/destiny/api/perks/match?q=&slot=&limit=` | `slot` = barrel / magazine / perk1 / perk2 | `{results: Perk[]}` con score + useCount |
| `POST` | `/destiny/api/add` | `{itemHash, barrel, magazine, perk1, perk2}` | `201 {weapon}` / `409` duplicado / `400` perks inválidas |
| `POST` | `/destiny/api/update` | `{itemHash, barrel, magazine, perk1, perk2}` | `{weapon}` |
| `POST` | `/destiny/api/remove` | `{itemHash}` | `204` |
| `POST` | `/destiny/api/toggle-found` | `{itemHash}` | `{found}` |
| `GET` | `/destiny/api/icon?type=weapon\|perk&hash=` | — | imagen (R2 → Bungie fallback), `max-age=2592000` |
| `GET/POST` | `/destiny/api/perk-icon` | listar / agregar / borrar / set-category del pool custom | — |

`src/lib/d2/resolver.ts` (`resolveWishlistRow`) arma el shape final para el cliente.

La búsqueda de armas se usa como type-ahead en "Agregar arma": con `q` vacío o
sin coincidencias devuelve `result: null`; el cliente muestra "Sin
coincidencias" en ese caso.

## UX

- Filtros por estado (Todas/Pendientes/Encontradas) + por tipo de arma (chips pill con conteo).
- Type-ahead en inputs de perk: 3 fuentes con dedup (wishlist del user → `d2_perk_icons` → manifest solo si hay `q`). Orden: `_score` ASC → `useCount` DESC → nombre ASC. Chip `×N` si `useCount > 1`.
- Dropdown `position:fixed` con coords del viewport (`getBoundingClientRect`, `z-index:9999`) + **atomic reveal** (coords antes de remover `hidden`) + re-posicionamiento en scroll/resize (ignora scroll interno del dropdown). `state.perkConfirmed[slot]` evita reabrir tras selección. Sin auto-focus en el primer input.
- Dialogs con `overflow-y-auto` + `overscroll-contain` + `lockBodyScroll()` con compensación de scrollbar.
- Container `max-w-[1760px] 2xl:max-w-[2240px]`, grid fluido.
